# AI Account Switcher v0.6.0

This release fixes Codex auto-prime confirmation by making the priming request finish like a real
Codex turn before the app starts watching `reset_at`.

## What Changed

- Codex prime now drains the `/backend-api/codex/responses` SSE response body before D3 is considered
  successful. The previous path treated the initial HTTP 2xx as "sent OK" and dropped the stream
  immediately, which could cancel the tiny turn before provider-side accounting anchored the 5-hour
  window.
- The Codex prime payload stays lightweight and asks for an `OK` reply only, so the completed stream
  is cheap while still behaving like a normal finished request.
- Prime logs now say "prime request" and only report D3 success after both HTTP 2xx and response-body
  completion.
- Added a unit guard for the Codex prime payload so future edits keep it streamed, non-stored, and
  brief.
