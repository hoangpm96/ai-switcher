# AI Account Switcher v0.6.3

This hotfix closes the gap left by v0.6.2: Claude scheduled auto-prime could still trigger a macOS
folder-permission prompt and stall until the auto-prime deadline expired.

## What Changed

- v0.6.2's `--exclude-dynamic-system-prompt-sections` only moves cwd/git-status context out of the
  system prompt — it does not skip collecting it. Claude Code still runs `git remote` / `git ls-files`
  against the current directory on every invocation, including a plain `-p hi` background prime.
- Live TCC logs (`log show --predicate 'subsystem == "com.apple.TCC"'`) confirmed macOS attributes
  that `git` child process's `SystemPolicyAllFiles` preflight to the spawning app — producing the
  folder-permission popup and hanging the CLI until the scheduler's timeout killed it.
- Background Claude primes now shadow `git` on the child process's `PATH` with a no-op stand-in
  placed ahead of every other entry, so the real `git` binary never runs and there is nothing for
  macOS to prompt for.
- Verified live: the CLI still authenticates and completes normally, in well under a second instead
  of stalling for the full timeout.

## Verification

- `cargo build` and `cargo test --lib` (99/99 pass, including new PATH-ordering and shim tests)
- `cargo clippy --lib`
- Standalone end-to-end check: spawned the real `claude` binary with the exact args/env/PATH the
  background prime uses; the shim log confirmed `git remote` calls were intercepted and never reached
  the real `git` binary.

## Install

Download `AI.Account.Switcher_0.6.3_universal.dmg` from the release assets and drag the app into
Applications.

The build is not code-signed. On first launch, right-click the app and choose **Open**, or run:

```bash
xattr -cr "/Applications/AI Account Switcher.app"
```
